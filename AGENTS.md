# Инструкции для кодовых агентов в этом репозитории

Перед изменением кода прочитайте `README.md`, `docs/requirements.md`, `docs/contracts.md`, `docs/roles.md` и `docs/plan.md`. `docs/contracts.md` — согласуемый проект контракта; сообщайте о нужных изменениях до расхождения frontend/backend/emulator.

Ролей две. №1 — разработчик с GPT Astra: backend, архитектура, расчёт аналитики, надёжность, безопасность и запуск. №2 — второй разработчик: frontend, эмулятор, данные, интеграционные адаптеры, спецификация и кодогенерация, CI и материалы защиты. Границы файлов и совместных изменений определены в `docs/roles.md`; сгенерированные файлы вручную не редактировать.

Приоритет: работающий сквозной путь событий, история изделия, решение контролёра и доказуемые крайние случаи. Синтетические данные допустимы, но их нельзя представлять как производственные. CV в MVP не требуется. Нельзя автоматически выводить вину оператора из порядка обнаружения дефекта.

Исходные события неизменяемы; решения добавляются отдельно. Различайте время возникновения и приёма, логический дефект и отдельные наблюдения, неизвестное состояние и отсутствие признаков. Повтор события не должен удваивать KPI.

Не заявляйте реализованными интеграции, защиту, масштабирование и криптографию, пока нет кода и воспроизводимой проверки. Секреты, ключи и реальные персональные данные в git не добавлять. Обновляйте README и сценарий демо по фактической реализации. В завершении работы указывайте изменённые файлы, команды запуска/проверки и ограничения.
