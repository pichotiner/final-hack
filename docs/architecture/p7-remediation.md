# P7 — исправления по финальному ревью

Поручение владельца от 26 сентября 2026: реализовать весь список финального ревью. Редактор общей семантики, контракта и README — роль №1. Предыдущее архитектурное review выполнено; этот документ фиксирует решение до изменения потребителей. Независимое согласие роли №2 не заявляется.

## Решение

- Одна оценка контрольной точки определяет карту и gate. Неустранённый плохой вход блокирует точку даже при наличии хорошего. Отклонённый человеком ложный признак исключается из противоречия с явной ссылкой на решение; качество самого осмотра reject не улучшает.
- Recovery — отдельные идемпотентные команды контролёра по закреплённому B: связать неразрешённый осмотр с зарегистрированной сессией/циклом, заместить плохой осмотр сопоставимым пригодным повтором. Исходники не меняются; решения и эффективные привязки сохраняются отдельно. Команда scope проверяет B всех текущих изделий и снимает ровно одно ограничение. Метод, область, время и качество не исправляются утверждением оператора.
- `sending` — публичное состояние аренды. Timeline сортируется по времени возникновения и стабильным tie-breakers; cursor закрепляет ревизию истории, изменение между страницами требует перезапуска чтения.
- Analytics: явная когорта; inspected за всю историю отдельно от покрытия активного цикла; повтор считается по raw-осмотру. Период относится к возникновению осмотра/завершению операции. Разрезы содержат основания; неизвестные атрибуты не приписываются оператору. Длительности разного вида и происхождения не смешиваются. Ошибки — только установленные человеком, знаменатель — сопоставимые завершённые операции.
- Разбор обстоятельств — детерминированное сравнение пригодных сопоставимых контролей и связанных действий/состояний. Это гипотезы и ограничения, не автоматическая установленная причина.
- UI выбирает объекты из закреплённого контекста; новые ID сессий/плана создаёт автоматически. Повторная аутентификация сохраняет pending bytes/key и проверяет ту же личность.
- Read side читает согласованный snapshot без writer-lock. B готовятся на записи. Immutable B и outbox хранятся отдельно от текущего состояния; версии состояния содержат ссылки вместо вложенных копий. Старые данные читаются совместимо, история не удаляется. ACK не переписывает предметный агрегат.
- Keyring хранит active и предыдущие ключи. Пилотный профиль завершает TLS на reverse proxy, не публикует БД/API/ERP наружу; backup включает БД, ERP и отдельно защищённые ключи. Восстановление проверяется на изолированной базе с проверкой raw/B и повторной доставкой.

## Альтернативы и цена

Транспорт P7 — `contracts/openapi.yaml` **0.5.0**. Review редактора: новые DTO
session/recovery/scope/analytics, дополнительные необязательные поля чтения,
расширения enum `Delivery.status` (`sending`) и `Decision.action` согласованы с
runtime и UI этой поставки. Расширения enum требуют обновления клиентов со
строгим исчерпывающим разбором. Shape baseline регенерируется для этой версии;
это принятие новой формы, не доказательство обратной совместимости 0.4-клиента.
Внешний ERP-контракт остаётся **0.4.0**; независимое review роли №2 открыто.

Автоматическое «последний хороший победил» отвергнуто: теряет необъяснённые противоречия. Ручная правка SQL отвергнута: обходит аудит. Полный асинхронный ES/read-side требует нового протокола lag; сохраняем транзакционное модульное ядро. Цена выбранного решения — новые DTO, отрицательные сценарии, подготовка B на записи и совместимое чтение старого формата. Общий guard для предметных записей остаётся до измеренного обоснования более узкой блокировки.

## Проверка

Два контрпримера карты; poor → repeat → release; unresolved → bind с retry/stale/чужим raw; scope → одновременный импорт; GET во время sending; страницы timeline и late; разрезы/единицы KPI; смена credential после потерянного ответа; неизменность старого B; GET под writer-lock; ACK без роста state; restart key v1/v2; TLS и изолированный backup/restore. ### Что исправлено при завершении

Остаточные E501 устранены разбиением строк без изменения текста. Nginx был исправен:
unhealthy возникал из-за флага `wget`, отсутствующего в BusyBox. Healthcheck заменён
на `curl --cacert` с сохранением проверки TLS. Интеграционные ожидания обновлены
для OpenAPI 0.5.0 и B ревизии 0; проверка `sending` теперь читает все страницы
доставок, поскольку fixture разделяет БД между тестами. Playwright выбирает поля
по началу label, чтобы текст option новых действий не создавал неоднозначности.
Seed читает UTF-8 явно. Добавлен воспроизводимый populated restore smoke.
