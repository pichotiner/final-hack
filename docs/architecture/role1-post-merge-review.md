## 4. Путь интеграции

`git merge-tree --write-tree --messages HEAD origin/feat/role2-dp01-contract`
проверил объединение без изменения рабочей копии и вернул шесть конфликтов:
`adapters/postgres.py`, `adapters/quality.py`, `api/__init__.py`, `api/server.py`,
`domain/quality.py`, `tests/integration/conftest.py` (все внутри `backend/`).

Дополнительно обнаружены предметные несовместимости:

- №7 использует lock `("unified-pilot", namespace)`, P4 —
  `("production-guard", "demonstrator")`. Это разные блокировки, одновременный
  запуск writers не обеспечивает общего guard.
- `0004_unified_chain` и `0004_production_context` имеют одного родителя
  `0003_quality_workflow`. Простое сохранение обеих миграций создаст два Alembic
  head; это не исправляется разрешением текстовых конфликтов.
- №7 пишет `quality_items` из отдельного `unified_state`, без актуальной цепочки
  `storage_revision`/`quality_state_versions` P4. Совмещать такие writers нельзя.

Выбор №1: сохранить P4 как единственное ядро/guard/источник outbox, подключать
контракт, UI и ERP-компоненты №2 адаптерами. Нужные части B переносить из сохранённых
оснований P4 с raw provenance; не запускать второй coordinator рядом. Это план
интеграции, не выполненное объединение backend и не подтверждённый ERP ACK.

**Следующий результат №2:** отдельная корректирующая поставка контрактов/generated,
сессий, B, ERP disposition и UI по опубликованным R1-PR6-01–06/P4.
**Следующий результат №1:** адаптация команд/чтения и wire payload к исправленным
схемам, сохранение исходного body для dedupe, один outbox до digest, затем общий
A04 и сверка ERP ACK. Общие архитектурные вопросы повторно владельцу проекта
не передаются; адресные замечания публикуются непосредственно в PR №7.
