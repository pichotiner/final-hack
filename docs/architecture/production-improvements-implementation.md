## Решение и выбранный эксперимент

Проблема: новые сигналы требуют проверяемого поведения до внедрения в транзакции
выпуска. Альтернативы: сразу изменить API/таблицы; сделать отдельное приложение;
сначала проверить чистые вычислительные правила на независимых сценариях и
подключить безопасные чтения существующего B. Выбран третий вариант. Цена —
эксперимент ещё не обеспечивает долговечность, авторизацию и реальную доставку.
Проверка — детерминированные входы и независимые ожидания, пропуски/дубли/поздние
данные, затем review и интеграционные тесты одного ядра. Если интеграция требует
второго журнала решений или изменения правил выпуска без версии — пересмотреть.

## Предлагаемая серверная интеграция: на review №1

| Область | Источник / право | Сохранение и семантика |
| --- | --- | --- |
| Готовность поста | Источник метрологии/АСУ ТП | Проверки эталона, света, фокуса, канала, калибровки и часов, время истечения; false/unknown не превращать в ready |
| Инструмент | MES/мастер | Интервалы установки по оборудованию/позиции, авторитетные run, материал/программа и профиль; пересечение установок означает неоднозначность |
| Партия/карантин | Поставщик даёт протокол, ОТК назначает проверку | Точные/возможные связи; предложения охвата отдельно от подтверждённого брака; применение через общий scope workflow |
| Следующий контроль | Утверждённый профиль технолога | Только допустимые методы по неизвестным основаниям и альтернативам; версия рекомендаций сохраняется с назначением |
| Передача смены | Мастер создаёт, принимающий мастер подтверждает | Снимок открытых задач с revision, отдельная квитанция приёма; новые задачи не считаются переданными задним числом |
| Тревоги/индикация | Источник создаёт, оператор подтверждает | Ключ source/equipment/channel/rule/run; версии активности, ACK и закрытие отдельно, повтор не подаёт новый звук |
| Объяснение B | Чтение существующих DTO | Сравнение только одного item и target, различия входов/версий/полноты/ограничений, без догадки о физической причине |

Новые события сохранять существующим защищённым приёмом с правами источника;
состояния и задачи — в той же PostgreSQL под `production_guard`. Новый command
receipt должен включать ID/revision и идемпотентность actor/target/key/body.
Отзыв доступа при повторе не доказывает отказ исходной команды. ACK звука не
является ACK ERP. Изменение обязательных требований контроля и ограничений выпуска
делается только версионированной предметной командой, старое B неизменно.

**Нужно от №1:** согласие с семантикой/DTO, редактор OpenAPI, способ переноса
событий готовности/установок/партий в B и scope, права команд handoff/ack/close.
Запрос передан комментарием PR №10. До ответа автономный эксперимент не
представляется как сохраняемый производственный workflow.

### Семантические границы

Готовность проверяется только по переданному снимку, реальная камера не подключена.
Установки — полуоткрытые интервалы; смена инструмента внутри run означает
неопределённость. Профиль связывается с оборудованием/позицией/инструментом/
материалом/программой. Факты партии и исторические связи выбирает вызывающая сторона:
эксперимент не извлекает их из сегодняшнего состава. «Точно затронуто» означает
связь, не доказанный дефект. При неполном каталоге нельзя гарантировать весь охват.

Выбор следующего метода минимизирует худший остаток альтернатив по утверждённой
таблице исходов, затем стоимость в минутах. Вероятностей причин нет: это не
оптимизация ожидаемой экономии. Методы другой области/материала, неполные или
неутверждённые профили не используются.

Квитанция передачи — неизменяемый результат функции; записи о задачах не меняются,
задача не закрывается от ACK. В runtime квитанция и смена владельца должны стать
одной серверной транзакцией. Ответственность за разбор неизвестной команды можно
передать, её исходный actor/body/key менять нельзя.

Тревоги воспроизводятся в порядке приёма, имеют стабильный ключ и отдельно
признак восстановления/подтверждения/закрытия. Исторический сигнал сохраняется,
но не выдаёт новый звуковой token за пределами окна свежести. Token в эксперименте
не означает физическую доставку. В HTML память прозвучавших эпизодов ограничена
страницей; перезагрузка молчит до нового нажатия, но повторное ручное нажатие
после перезагрузки может снова проиграть пример. Промышленная дедупликация звука
после restart требует хранения у edge — не проверена этим опытом.

Карта этапов считает по уникальной паре item/stage в заданной когорте. Нулевая
оценимость даёт `null` доли обнаружения. `origin_established=false` означает,
что происхождение на этом этапе не установлено, а не доказанное отсутствие
причины. Частота установленных происхождений — нижняя наблюдаемая оценка,
не полное распределение реальных причин.

### Проверки и воспроизведение

Из backend:

```bash
python -m pytest -m 'not integration' -q
python -m scripts.production_improvements_demo --html /path/to/new-preview.html
```

Из frontend:

```bash
npm ci
npm test
npm run check:generated
npm run build
npx playwright install chromium
node scripts/check-production-preview.mjs file:///absolute/path/to/new-preview.html
```

Проверка браузера исполняет настоящий JavaScript/Web Audio: два вызова oscillator
для двух проблем, повторное нажатие не повторяет их, ACK оставляет проблему открытой,
при потере мониторинга нет новых звуков, загрузка страницы сама не звучит. Это
проверка вызовов аудио API в Chromium, не физическое прослушивание динамика.

Фактический прогон №2: **178 backend tests passed, 71 integration deselected**
(из них **18** новых проверок правил и примера); **18 frontend tests passed**
(5 новых: 4 для объяснения/подсказок и 1 для гонки сравнения). TypeScript generation,
TypeScript/Vite build, Ruff и `git diff --check` прошли. Перед frontend-сборкой
выполнен `npm ci` по актуальному lock: оставшиеся от прежней ветки зависимости
не содержали `@types/node`, после установки сборка прошла.

Браузер: Playwright Chromium 141 / headless, штатный Web Audio. На Linux
недостающая libasound распакована в `/tmp/opencode/browser-libs`, путь передан
через `LD_LIBRARY_PATH`; системные библиотеки не заменялись. Проверка выполнялась
на сгенерированном [локальном примере](../experiments/production-preview.html).
Результат правил сохранён [отдельно](../experiments/production-result.json).
Полный A04/БД, аппаратный звук, восстановление edge и реальные credentials
новых действий в этой поставке не проверялись.

**Блокирующая следующая поставка №1:** общий контракт и транзакционное включение
новых фактов/команд. После этого №2 подключает серверные экраны готовности,
