# Передача роли №1: довести единую цепочку до доказательного M0

Владелец следующей поставки: роль №1, GPT Astra. Редактор этого задания — роль №2 по итогу совместного маршрута; роль №1 принимает/исправляет семантику ядра до изменения общих контрактов. База — [единая архитектура](unified-system.md), [DP-01](decision-protocol.md), [ответ R2](role1-response-to-role2-review.md), [review №2](role2-response-to-role1-decisions.md). **Это план, не заявление, что перечисленные механизмы уже реализованы.**

Порядок каждого решения: проблема → 2–3 альтернативы → выбор → цена → отказ → проверка → условие пересмотра. Единый редактор контракта согласует изменение семантики с обеими ролями, потом обновляет schema/generated/потребителей; входной envelope 1.0 и v0.2 не менять молча.

### Немедленные вопросы к №1 перед общим freeze

1. Подтвердить R2-F01: исторический цикл обходится, конфликт текущего состава сохраняется как unknown, resource limit откатывается целиком. Определить, кто и как снимает открытое ограничение.
2. Подтвердить R2-F02: центральный disaster restore — M0-R; рестарт ERP/worker и потеря ACK — M0.
3. Принять/исправить R2-F03: `control_record_ids` ссылается на raw контроль `no_defect_signs` (спорный предложенный транспорт), `observation_id` в quality слое — отдельный серверный ID контроля/признака; подтвердить единственный тип ссылки для публичного resolve. Никаких фиктивных defects[] для отрицательной проверки.
4. Проверить, что `open_item`, импорт, состав/пересвязка, решения, replay и scope используют согласованную транзакционную границу; упрощённый `UnifiedChain` эталон одного пилота, не полноценная платформа нескольких площадок.
5. Зафиксировать версию и доступность правил/метода в B, честную доступность медиа и ручное разрешение противоречащей точки при финальном release.

**Критерий остановки:** оба участника могут за три минуты пройти R1–R11, повтор, изменение состава, B1/B2 и результат ERP без исправления raw или назначения виновного по времени. Отчёт M0 содержит команды/ID, доказанные результаты и отдельные ограничения. Изменение v0.2/DP-01 проходит review обеих ролей, после чего обновляются DTO/UI/expected. README и общую схему редактирует один назначенный редактор; этот документ — передача для review №1, не общий freeze.
