## 1. Один маршрут и три независимых экземпляра

Заказ `order-001`, тип `bracket-demo`, маршрут `route-bracket@1`, план контроля `1`.
Изделия `assembly-001/002/003`; у каждого собственные `bracket-00N` и `insert-00N`.
Посты `station-machining` и `station-assembly`, условные исполнители `operator-01`
и `operator-02`, оборудование `machine-01/02`, смена `shift-1`.

| Точка / действие | Привязка начального цикла assembly-001 | Предметное условие |
| --- | --- | --- |
| Входной контроль `incoming-surface` | session `assembly-001-initial-incoming`, run отсутствует | insert-001, face-A, incoming; эксклюзивное назначение комплекту — допущение, не установка |
| Обработка | `run-machining-001`, первый пост/оператор | Отдельные start/finish; полное время на посту, не автоматически активное время |
| `after-machining` | session `assembly-001-initial-machining`, run обработки | after_operation, та же область и допустимый метод |
| Сборка | `run-assembly-001`, второй пост/оператор | Факт установки требует отдельного владельца, список компонентов заказа его не создаёт |
| `final-surface` | session `assembly-001-initial-final`, run сборки | final; видимость face-A после сборки — допущение |

Источник контроля `vision-emulator-1`, метод `emulator-1`; факты операций/действий/
станка — `line-emulator-1`. Это один синтетический источник наблюдений с заданным
track `mark-001`, а не доказанная способность трёх камер узнавать один дефект.
Медиа отсутствуют; интерфейс не показывает фиктивное фото.

Для доработки нужен новый серверный cycle ID, новый run со ссылкой на старый и
три новые зарегистрированные сессии. У повторного incoming run отсутствует;
after-machining/final связываются с допустимым rework run по повторному плану.
Это синтетическое правило плана; применимость такого контроля на заводе утверждает
технолог. Все три повторные проверки в A04 выполняются после завершения доработки.
Перенос старой проверки рассматривается отдельно в A06 и не обходится старой сессией.

## 2. Матрица источников и конфликтов

| Данные | Ответственный владелец | Версия/основание | Что делать при расхождении |
| --- | --- | --- | --- |
| Заказ, список изделий | Планирование / ERP | external_system + external_order_id + revision, исходный пакет | Неизвестный mapping — отказ/разбор; новую revision не подставлять в старый B |
| Маршрут и обязательные точки | Технолог | Утверждённые route/control-plan версии и применимость | ERP — канал передачи; не может самостоятельно отменить контроль |
| Недостающие bindings демонстратора | Интегратор по плану технолога | profile ID/version, source authorities, item/component mapping, sessions/run | Мутация опубликованного профиля запрещена; ошибку исправлять новой версией |
| Проектный BOM | Конструктор / PLM или экспорт КОМПАС | Версия чертежа, позиции/тип/количество/единицы | Без геометрии это указать; требуемая деталь не равна установленному экземпляру |
| Установка/снятие | Мастер и производственный учёт/MES | Сканы, операция, утверждение и границы полноты | Конфликт текущего состава оставляет неизвестность; инженер не выбирает «последнего ответившего» |
| Операция/исполнитель | MES или назначенный журнал участка | Уникальный run, start/finish, станция, смена | Пропущенный finish — незавершённость, время неизвестно; не 0 секунд |
| Состояние станка | АСУ ТП / журнал оборудования | equipment/run, единицы параметров, время | Warning — обстоятельство, не доказанная причина |
| Наблюдение | Допущенный источник/метод | source/event, session, область, метод, качество | Poor/unknown не закрывает точку; чужой ID или метод требуют разбора |
| Решение | ОТК | Автор сервера, причина, B/revision, история | Устаревшее основание требует нового просмотра, не тихого обновления формы |
| Применение внешнего результата | ERP-получатель | stream/message/version/digest + первоначальный ACK | Сверка при lost ACK; физическое удержание подтверждает мастер отдельно |

Для предприятия запросить: версию/конфигурацию ERP и поддерживаемый интерфейс;
владельца маршрута; источник серийных ID; журнал установки/снятия и полноту выгрузки;
допустимый offline-интервал; сроки хранения; допустимый размер файлов; ответственных
смены; ручной порядок контроля и удержания. До ответов это проектное назначение.

## 3. Отказы: что видит человек и кто действует

Все физические действия ниже — регламент предприятия, не управление станком из EFQA.

| Отказ | Что сохраняется / что видит оператор | Ответственный и выход из отказа |
| --- | --- | --- |
| Камера/триггер не дали кадр | Пробел обязательной точки, отсутствует фиктивное «дефектов нет» | АСУ ТП восстанавливает; ОТК назначает новую/альтернативную проверку |
| Блик, смаз, неизвестная модель | Исходный сигнал и неоценимость/неприменимый метод | Технолог/ОТК проверяют метод; новый допустимый контроль, старый raw остаётся |
| Скан A, физически B | Привязка считается сомнительной при обнаруженном расхождении | Мастер сверяет экземпляр и комплект; отдельное разрешение по доказательствам |
| Часы расходятся | Оба времени и uncertain; причинный порядок не доказан | АСУ ТП восстанавливает синхронизацию; прежние timestamps не переписываются |
| Центр недоступен | В целевом Edge — очередь, возраст/объём; локальное сохранение не выпуск | ИТ восстанавливает; мастер/ОТК сверяют накопленные и ручные записи |
| Квота 70/85/95% | Предупреждение / ручной режим / отказ новому захвату без резерва | Эксплуатация и мастер; unacked не удаляются; возобновление после сверки |
| Питание/диск Edge | Незавершённый захват отдельно; исправный durable диск допускает recovery | ИТ/АСУ ТП; потеря единственного диска не покрывается local ACK |
| ERP недоступна | Решение сохранено, доставка ожидает/ошибка; не «ERP приняла» | Интегратор; повтор неизменного сообщения, затем сверка ACK |
| Ответ команды потерян | «Результат неизвестен», прежняя команда сохранена | ОТК/ИТ восстанавливают доступ, точный повтор/авторизованная сверка |
| Перезапуск API/worker | Данные БД и очередь прежние | ИТ; истечение аренды и безопасный retry; не доказательство disaster restore |
| Потеря центра/restore старой копии | Возможны утраченные решения и версии | Отдельный M0-R: backup/ключи/ERP-сверка до исходящей доставки и допуска ОТК |

## 4. Ресурсы и границы опыта

Выбор M0: структурированные события без фото. Альтернатива с реальными изображениями
требует архива, доступности файлов и отдельной проверки метода; сейчас это не даёт
лучшего доказательства B/late/ACK и увеличивает объём интеграции. Пересмотр — если
заказчику нужно проверить конкретную визуальную задачу или фото обязательно для ОТК.

Проектные числа из edge-deployment: 2 события/с × 4 KiB × 8 h = 225 MiB тел;
с запасом 2 и overhead 2 — 900 MiB. Это расчёт, не испытание отключения питания.
Для 0,1 осмотра/с, двух файлов по 2 MiB: 27 GiB за 8 h с запасом/overhead.
Несжатый кадр 2448×2048×8 bit = 4,78125 MiB; тот же бюджет становится 64,546875 GiB,
превышая 64 GiB media-квоту. Следовательно, прежний диск не обещает 8 h для raw-фото.
Проверить фактические размеры, recovery-архив и суммарную квоту до физического пилота.
При 20 принятых событиях/с и новых 2/с разгрузка 57 600 событий — минимум 3 200 s.
20/с — предположение, а не замер ядра; если доставка не быстрее поступления,
добавление диска не решает накопление.

## 5. Аналитика и ограничения вывода

Когорта первого опыта — явно выбранные три изделия, история целиком. Отдельно
показывать lifetime «хотя бы раз проверялось» и полноту активного цикла. Периодный
фильтр требует явного выбора времени и не считается автоматически реализованным.
Два кадра/сообщения одного mark не равны двум дефектам. Два разных mark на одном
изделии — два кандидата и не более одного изделия с дефектами после подтверждения.
Идентичность между разными источниками не угадывается.

Входное обнаружение, первое обнаружение после операции и установленная причина —
три разных показателя. Для сопоставления работ нужны одинаковые тип изделия,
операция и маршрут; при отсутствии данных рейтинг операторов не строится.
Длительности в этом пакете — station_elapsed из start/finish; active_processing
не выводится автоматически. Требуемые PDF разрезы перечислены в приёмочной карте:
их отсутствие в P5 следует зарегистрировать как остаток MVP, а не скрыть за A04.
