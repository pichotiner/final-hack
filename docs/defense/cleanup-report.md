1 545 702 байта**, затем пустой каталог `integrations`. Отслеживаемые Git исходники
не удалены: среди них не найдено доказанно ненужных файлов.

## Проверка 1 — что это за файлы

Сверены с `git ls-files`: ни один кандидат не является исходником в Git.
Содержимое Python-кэшей — только `.pyc`; остальные кандидаты — кэши pytest/Ruff,
выход Vite и старый TypeScript build-info. Сняты количество и размер файлов.
`integrations` содержал только два `.pyc` от отсутствующих исходников старой ветки.

## Проверка 2 — можно ли удалить

Повторно сверены состав и размер после первой проверки. Каждый файл проверен
`git check-ignore`: все кандидаты игнорируются по правилам проекта. Точные пути
проверены в отслеживаемых исходниках, конфигурации, Dockerfile и документах:
ссылок не найдено. В `frontend/package.json` сохранена команда восстановления
сборки, `tsconfig.json` использует `noEmit`; содержимое `dist` не является исходником.
После второй проверки кандидаты удалены.

Группы: корневые/серверные `.pytest_cache` и `.ruff_cache`, Python `__pycache__`
в backend/contracts/emulator/docs/research/integrations, `frontend/dist`,
`frontend/tsconfig.tsbuildinfo`.

## Что сохранено и почему

- Старые архитектурные документы и review — история решений, ссылки, ограничения
  и основания проверок. Их содержание включено в единый PDF с пометкой архива.
- Generated и compatibility baselines — потребители контракта и проверки дрейфа.
- Миграции и legacy entrypoint — совместимость и интеграционные тесты, не мусор.
- Два исходных PDF — нормативная постановка и критерии.
- Видео, кадры, JSON P6 — реальные свидетельства опубликованного прогона.
- `node_modules` — установленные зависимости рабочего стенда, а не архив документов.
- Старые слайды `docs/demo/slides.html` — часть воспроизводимого пакета роли №1;
  новая шестиминутная презентация опубликована отдельно.

Локальные удаления игнорируемых файлов не появятся в diff PR и не очистят рабочую
копию другого участника автоматически. Массового удаления по возрасту или имени
не выполнялось. Для повседневной подготовки используйте только `docs/defense/README.md`:
больше не нужно просматривать весь архив.

## Проверка готовых материалов

Сборщик читает исходные Markdown, формирует список всех включённых документов
с SHA-256 и проверяет сумму таймингов 360 секунд. PDF содержит встроенный кириллический
шрифт и закладки разделов; PPTX — редактируемые текстовые блоки и заметки докладчика.
Существующий P6 не запускался повторно: в презентации его результаты атрибутированы
отчёту роли №1. Новый текст и идеи не повышают статусы BLOCKED/PARTIAL до PASS.

Фактические результаты: 57 исходных документов сверены по manifest, все Markdown
в `docs/` вне каталога сборки включены; 274 страницы книги, 8 страниц презентации,
8 слайдов PPTX с совпадающими заголовками и заметками. Все фигуры PPTX находятся
в границах слайда. Тайминг — 360 секунд, текст выступления — 627 слов плюс показ
схемы/кадра. PDF-слайды отрисованы `pdftoppm` и просмотрены, кириллица извлекается
`pdftotext`, DejaVu Sans встроен по `pdffonts`. Локальные ссылки проверены, Ruff
для сборщика и `git diff --check` прошли. PowerPoint визуально в приложении не
открывался; для показа подготовлен отдельно проверенный PDF.
