| Время | Кадр / действие | Реплика и проверяемое утверждение |
| --- | --- | --- |
| 0:00–0:25 | Чистый запуск, эмулятор, входное задание `order-001` | «Задание приходит от отдельного ERP-эмулятора»; показать HTTP/экран задания |
| 0:25–0:55 | Линия и список изделий | «Несколько изделий, два участка; численные показатели поступают с сервера» |
| 0:55–1:25 | Паспорт `assembly-001`, состав и лента | «У каждого события видны время возникновения и приёма; операции имеют отдельные ID» |
| 1:25–2:05 | Карточка с двумя наблюдениями `mark-001` | «Это один логический дефект; гипотеза причины не является решением контролёра» |
| 2:05–2:35 | Решение `confirm`, причина `unresolved`; затем `rework` по изделию | Показать автора, основание, новую ревизию и независимость итогового статуса |
| 2:35–2:55 | Аналитика и исходящий результат | `1` изделие с подтверждённым дефектом, `1` дефект, `0` ошибок оператора; показать ACK message ID |
| 2:55–3:25 | Replay дубля и позднего события | Показать неизменность KPI от дубля, позднее основание и `review_required` |
| 3:25–3:45 | CI/контракт и границы | Кратко показать совместимость, честно назвать синтетический источник и неподключённые ERP/CAD |

Снять результаты одного непрерывного прогона; не подставлять заранее нарисованные KPI. Для проверки целостности вставить действие, согласованное с ролью №1.
