# Внешние обмены и владельцы данных

Работающий внешний сервис в этой ветке — только **ERP-эмулятор** на `:8090`. Прямые подключения к 1С, Галактика:ERP, MES и КОМПАС-3D здесь не реализованы. `integrations/adapters.py` содержит проверяемые преобразования демонстрационных файлов на границе системы; вызов из backend подключает роль №1 через свой порт интеграции.

| Источник | Владеет | Вход в ядро / выход из ядра | Внешний ID и внутренний ID | Ошибка |
| --- | --- | --- | --- | --- |
| ERP-эмулятор | Задание, ревизия маршрута и список контрольных точек | `GET /external/v1/work-orders`, `POST /external/v1/quality-results` | `(erp-emulator, work_order, external_order_id) → work_order.id`; item аналогично | Неизвестная ревизия и конфликт ID не переписывают импортированное задание; результат остаётся в outbox до ACK |
| 1С | Заказ и номенклатура при реальном подключении | Пример JSON `examples/1c-order.json` → `from_1c_order` | `(1c, work_order, НомерЗаказа)` и `(1c, item, СерийныйНомер)` | Пустые ID отклоняются, существующее соответствие другому ID даёт конфликт |
| Галактика:ERP | Заказ и маршрут при реальном подключении | `examples/galaxy-order.json` → `from_galaxy_order` | `(galaxy, work_order, orderNo)` и `(galaxy, item, batchItemNo)` | Ошибки формата и ревизии требуют разбора, не маскируются успехом |
| MES | Факт выполнения операции | `examples/mes-finished.json` → `from_mes_operation` | `(mes, item, unitId)` должен существовать до создания связанного события | Неизвестное изделие остаётся неразрешённым, не привязывается по похожему тексту |
| КОМПАС-3D | Версия состава сборки | `examples/kompas-assembly.json` → `from_kompas_assembly` | `assemblyId + version`, component ID/partNo | Неверное количество отклоняется; геометрии в файловом примере нет |
| Ядро качества | Наблюдения, карточки, решения, итог и аудит | `to_erp_quality_result` → эмулятор | Стабильный `message_id` на одну версию; новая версия с `previous_message_id` | 429/5xx/timeout повторяются с тем же ID; 4xx и конфликт тела требуют разбора |

В реальном подключении справочники и экземпляры должны иметь отдельные таблицы соответствий `(system, entity_type, external_id) → internal_id` с уникальностью. `IdMap` показывает правило конфликта, но хранит значения только в памяти и не является промышленным реестром. Роль №1 определяет постоянный порт и транзакции импорта/исходящего outbox; адаптер не рассчитывает KPI и не выводит причину.

Ответ эмулятора на повтор того же `message_id` и тела — `200 duplicate`. Тот же ID с иным телом — `409 rejected`. Заголовок `X-Emulator-Failure: 429|500|503|timeout` моделирует временную ошибку для проверки повторной доставки; это тестовый механизм эмулятора, не протокол ERP. SQLite сохраняет принятые сообщения между перезапусками. `GET /external/v1/quality-results` — демонстрационный просмотр сохранённых результатов.

Для прямых vendor API остаются отдельные задачи: согласовать официальные схемы и способы доступа с заказчиком, подписку/опрос и лимиты, кодировку и часовые пояса, обратные ссылки на версии, а затем проверить на тестовом контуре. Приведённые поля — наш пример контракта, не заявление о формате поставщика.
