# Изолированный показ P6

Один запуск поднимает **отдельную одноразовую БД PostgreSQL**, два живых HTTP
процесса (API и SQLite ERP), UI Vite и Chromium. При успехе записывает
непрерывное видео экрана, скриншоты и обезличенные результаты. Входной заказ,
профиль и synthetic credentials создаются в `.local/p6-*/`; секреты не входят
в опубликованные доказательства. Сохранённые здесь результаты соответствуют
конкретному прогону, не служат входами для проверок.

## Воспроизведение (PowerShell, Windows)

Требуются Docker Engine, Python 3.11, Node 24, npm 11. Из корня проекта:

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
cd ../frontend
npm ci
npx playwright install chromium
cd ../backend
.\.venv\Scripts\python.exe scripts/acceptance_demo.py --publish
```

`--publish` при **успешном** прогоне обновляет `docs/demo/` (видео, результаты,
A04, несколько кадров); без него доказательства остаются только в игнорируемом
`.local/p6-<id>/evidence/`. `--slow-ms 250` добавляет паузы между кадрами;
`--headed` открывает видимое окно браузера; `--serve` оставляет стенд после
прогона до Ctrl+C (том и процессы удаляются при выходе). `--output` принимает
только новый путь внутри `.local/`.

Данные: `docs/acceptance/role2-m0-inputs.json` (смысл сценариев) и отдельные
ожидания `docs/acceptance/role2-m0-expected.json`; серверные ID/cycle/B всегда
получаются от API. Дополнительные изолированные изделия генерируются из
закреплённого ERP-профиля без ручного изменения предметных таблиц. HTTP-трасса
каждого прогона остаётся в `.local` вместе с логами, но без bearer-заголовков.
Оригинал CLI-квитанции импорта — `evidence/import.jsonl`.

## Проверенные границы

Видеопуть: `assembly-002` normal release; `assembly-001` confirm → rework →
серверный цикл мастера → законченная доработка и три контроля → resolve →
released → ERP commit/lost ACK → повтор worker → сохранённое решение/B/ACK;
`assembly-003` poor+negative; отдельный browser lost response → 403 → точный
retry. Остальные семантические проверки идут через публичный HTTP на том же
изолированном стенде; подробности и **частично покрытые строки** — в
протоколе. Это не аттестация
промышленного окружения, физического ремонта или фактического качества CV.

`walkthrough.webm` — один непрерывный захват Chromium; действия источников и
worker снаружи браузера подтверждаются соответствующими квитанциями в
`a04.json` и `results-summary.json`. Экранные пароли замаскированы. Для
показа откройте [шесть слайдов](slides.html) локально и включите видео.
