Один заказ · два участка · три точки

ERP → профиль задания → входной контроль → механическая обработка / оператор 01 → контроль → сборка / оператор 02 → финальный контроль.

План ≠ факт. Камера и станок подают структурированные события; два времени и происхождение сохраняются.

Тогда / сейчас

Raw + provenance → кандидат → человек подтверждает → B закрепляет версию знаний → позднее наблюдение создаёт новое B и review.

Признак после операции ≠ установленная вина оператора. Плохое изображение ≠ отсутствие дефекта. Пропущенная точка блокирует выпуск.

Почему модульное ядро?

Один PostgreSQL guard: raw, история, решения, B, outbox. Адаптеры связывают ERP и UI через явные контракты.

Альтернатива: зрелая QMS с полным аудитом. Выбор пересматриваем, если она дешевле докажет прежние B, поздний факт, unknown и устойчивый ACK.
